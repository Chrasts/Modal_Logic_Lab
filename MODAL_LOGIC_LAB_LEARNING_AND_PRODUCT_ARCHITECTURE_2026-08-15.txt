4. HOW TO PLAY / LEARN THE CONTROLS
===================================

Účel:
učit workspace, ne modální sémantiku.

Obecné principy:
- šest krátkých kroků
- jedna hlavní interakce na krok
- nerelevantní controls skryté nebo locked
- žádná zbytečná modal theory
- žádná povinná prediction gate pro construction tasks
- explicitní objective
- krátký completion feedback
- poslední krok vede do prvního Learn chapter


MISSION 1: CHOOSE THE EVALUATION WORLD
--------------------------------------

Initial model:
- w0 bez atomů
- w1 obsahuje p
- bez hran
- evaluation world = w0

Task:
Select w1 and make it the evaluation world.

Unlocked:
- selection
- Set as evaluation world

Completion:
- evaluation world = w1

Feedback:
Formulas are evaluated relative to a selected world.


MISSION 2: EDIT A WORLD VALUATION
---------------------------------

Initial model:
- jeden world w0
- bez atomů

Task:
Add the requested atom to w0.

Unlocked:
- valuation editor

Completion:
- requested atom je true at w0

Feedback:
Atoms written inside a world are true at that world.


MISSION 3: DRAW AN ACCESSIBILITY RELATION
-----------------------------------------

Initial model:
- w0
- w1
- bez hran

Task:
Draw w0 -> w1.

Unlocked:
- relations

Instruction:
Drag from w0 to w1. Connection-handle position does not determine direction.

Completion:
- w0 -> w1 exists

Feedback:
Accessibility is directional. w0 -> w1 differs from w1 -> w0.


MISSION 4: CORRECT A RELATION
-----------------------------

Initial model:
- w0
- w1
- w1 -> w0

Task:
Replace w1 -> w0 with w0 -> w1.

Unlocked:
- relation selection/delete
- relation drawing

Completion:
- w1 -> w0 není explicitně přítomná
- w0 -> w1 je explicitně přítomná

Exact edge count vynucovat pouze tehdy, když je count skutečnou součástí
learning objective.

Feedback:
Select a relation to edit or delete it.


MISSION 5: ADD A WORLD
----------------------

Initial model:
- pouze w0

Task:
Add one new world and make p true there.

Unlocked:
- + World
- valuations

Completion:
- existuje nově přidaný world s p

V této controls lesson může být přesně jeden nový world rozumnou interpretací
"Add one world". Podobné size restrictions nepřenášet mechanicky do jiných
lessons.

Feedback:
Models can be extended by adding worlds and assigning their valuations.


MISSION 6: BUILD A SMALL MODEL
------------------------------

Initial model:
- pouze w0
- bez atomů
- bez hran

Task:
Create w1, make p true there and draw w0 -> w1.

Unlocked:
- worlds
- valuations
- relations
- Undo/Redo

Completion:
- w1 exists
- p is true at w1
- w0 -> w1 exists

Důležité:
extra irrelevant world nesmí sám způsobit failure. Cílem je zkombinovat controls,
ne testovat minimalitu.

Feedback:
You can now build the basic parts of a Kripke model: worlds, valuations and
accessibility relations.

Potom:
Continue to the first Learn chapter.

10. NOVÉ CAMPAIGN / PRACTICE FAMILIES
=====================================

10.1 Axiom Breaker
------------------

Implementovaná Practice family nyní obsahuje první dvě mise pro axiom 4 na
reflexive frame a axiom 5 na serial frame.

Příklady:
- falsifikuj axiom 4 při zachování reflexivity
- zachovej seriality a najdi countermodel k zadanému principu
- vytvoř symmetric non-transitive frame
- vytvoř valuation witnessing failure correspondence-related formule

Placement:
- Practice pro izolované úlohy
- Campaign pro tematickou sérii

První verze nepotřebuje nový Lab module.


10.2 Model Budget / Small Model Challenges
------------------------------------------

Implementovaná Practice family nyní obsahuje Split possibility a Two steps
away s explicitními world/relation bounds.

Používat explicitní constraints:
- at most N worlds
- at most N explicit edges
- required/forbidden relation properties
- semantic-change budget
- optional bonuses

Placement:
- Practice
- Campaigns
- Create templates

Terminologie:
bounded solution není automaticky minimal.

Neříkat "minimal model", pokud optimálnost nedokazuje solver/search.


10.3 Distinguishing Formula Challenges
--------------------------------------

Koncept:
na finite modelu a target world zadat formuli s požadovaným truth setem, často
jen target world.

Výuková hodnota:
- propojuje syntax a truth sets
- ukazuje limity modal expressivity
- vytváří přirozený bridge k bisimulation

Placement:
- advanced Practice
- rozšíření Formula Laboratory
- possible dedicated mini-campaign po Bisimulation

Důležité:
bisimilar worlds nemusí být žádnou modal formula rozlišitelné.

Formula length a modal depth mohou být metric/bonus.
"Shortest" nevyžadovat bez proof of optimality.


10.4 Bisimulation Game Campaign
-------------------------------

Po vzniku Lab toolu:
- identify legal Spoiler move
- choose Duplicator response
- find atomic mismatch
- find forth/back failure
- decide bisimilarity

Interactive game patří primárně do Lab.
Campaigns ho mohou obalit structured challenges.


10.5 Filtration Challenges

- ověřit truth preservation

10.6 Tableaux / Countermodel Challenges

15. PRINCIPY AUTHORING CONSTRAINTS
=================================

Používat constraints pouze tehdy, pokud vyjadřují skutečný objective.

Dobré:
- at most 3 worlds
- exactly one required relation, pokud je count součást úlohy
- frame must be reflexive
- learner může editovat valuations, ne relations
- konkrétní edge musí zůstat fixed
- solve within a defined semantic-change budget

Špatné:
- hidden restrictions
- reject extra irrelevant world, pokud minimality není objective
- vyžadovat přesný click order autora
- vyžadovat equality s reference solution
- nazývat bounded answer "minimal"

Pokud future task používá "steps", metriku explicitně definovat.
Preferovat semantic edits/change budget před UI clicks.

23. CONTENT DESIGN RULES
========================

Pro Learn/Campaign/Practice/Create content:

- mathematical objective musí být explicitní
- accepted solutions definovat sémanticky
- hidden restrictions eliminovat
- každé visible restriction musí mít pedagogický důvod
- hints mají progresivně odkrývat strukturu, ne pouze dát answer
- feedback má vysvětlit relevantní witness/counterexample
- detailní semantic evidence má být dostupná on demand
- visual model má zůstat po completion viditelný, kde je to užitečné
- lesson/challenge má být replayable
- difficulty má růst podle konceptu a samostatnosti, ne podle UI friction

Nepřidávat scoring/gamification jen proto, aby produkt působil více "game-like".
