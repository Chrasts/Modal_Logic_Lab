1. ZÁKLADNÍ VIZE
================

Cílem je vzdělávací a experimentální aplikace/hra, ve které je formální logika
přímo interaktivní mechanikou, ne pouze textovým nebo symbolickým cvičením.

Uživatel má umět:
- konstruovat a upravovat Kripkeho modely
- měnit valuace, accessibility relation a evaluation world
- zadávat nebo dostávat modální formule
- sledovat deterministické sémantické vyhodnocení
- řešit matematicky definované úlohy bez nutnosti trefit jeden uložený obrázek
- volně experimentovat mimo authored mise
- vytvářet a sdílet vlastní mise a kampaně

Správnost řešení musí určovat matematický objective, ne shoda s jednou
referenční konstrukcí.

Reference solution je svědek řešitelnosti. Není jedinou akceptovanou odpovědí.

Současné sémantické jádro je normální výroková modální logika nad explicitními
konečnými Kripkeho modely.

Dlouhodobě lze přidávat:
- epistemickou logiku
- doxastickou logiku
- temporální logiku
- dynamickou logiku
- public announcement logic
- deontickou logiku
- proof/search systémy
- pokročilé transformace a analýzu modelů

Tyto oblasti se nemají stavět současně.
Nevytvářet předčasně univerzální engine pro všechny budoucí logiky.

3. SOUČASNÉ IMPLEMENTOVANÉ SCHOPNOSTI
=====================================

3.1 Logický engine a sémantika
------------------------------

[IMPLEMENTOVÁNO]

- parser modálních výrokových formulí
- deterministický evaluator
- pointed evaluation M,w |= phi
- model-global evaluation M |= phi
- finite-frame validity F |= phi pomocí enumerace valuací
- formula comparison / equivalence v podporovaných scopes
- correspondence objectives
- rekurzivní evaluation traces
- semantic diagnostics a witness/counterexample informace
- frame-property checking
- frame constraints a relation-rule modes

Aktuálně podporované vlastnosti rámce:
- reflexive
- symmetric
- transitive
- Euclidean
- serial
- irreflexive
- acyclic

Automatické enforcement/closure je implementované pro:
- reflexive
- symmetric
- transitive
- Euclidean

Validation-only zůstávají vlastnosti, jejichž automatická oprava by vyžadovala
mazání dat nebo arbitrární volbu.

Standardní correspondence presets zahrnují:
- T / reflexive
- D / serial
- B / symmetric
- 4 / transitive
- 5 / Euclidean

Důležité omezení:
finite testing na jednom modelu nebo rámci není důkaz obecné modal validity ani
obecného correspondence theorem.


3.2 Parser formulí
------------------

[IMPLEMENTOVÁNO / REFINEMENT, P1]

Současný parser přijímá:
- Unicode: ¬ ∧ ∨ → □ ◇
- ASCII: ! & | ->
- textové unary keywords: box, diamond
- závorky
- alfanumerické názvy atomů s underscore

Parser už vrací přesnou pozici syntax error.

Blízký refinement:
- [] jako box
- <> jako diamond
- ~ jako negace
- případně textové not, and, or, implies
- malá explicitně dokumentovaná LaTeX-like vstupní vrstva:
  \Box, \Diamond, \neg, \land, \lor, \to, \implies
- normalizace aliasů před parsováním se zachováním užitečné pozice chyby
- live validation tam, kde reálně pomůže formula entry nebo authoringu

Nevytvářet plnohodnotný LaTeX parser.


3.3 Evaluation diagnostics a rozpad podformulí
----------------------------------------------

[IMPLEMENTOVÁNO / REFINEMENT, P1]

Již existuje:
- rekurzivní evaluation tree
- označení sémantického pravidla
- truth values
- kontroly successorů pro box a diamond
- witness/counterexample diagnostics
- strukturovaný success/failure/error result
- detailní semantic evidence on demand

[IMPLEMENTOVÁNO / REFINEMENT]
SUBFORMULA / EVALUATION EXPLORER

Cíl:
neudělat druhý evaluator, ale dát existujícím traces prostorovou a klikací vrstvu.

Požadované chování:
- zobrazit syntaktický strom podformulí nebo ekvivalentně přehledný decomposition
- kliknutí na podformuli zvýrazní její truth set na všech světech
- výběr □psi nebo ◇psi v konkrétním světě zvýrazní relevantní successory
- failure zvýrazní critical world a tam, kde to dává smysl, i konkrétní relaci
- umožnit přepnutí mezi "formula structure" a "evaluation at this world"
- znovu použít současný AST a evaluator

Příklad:
při vyhodnocení □p ve w1, pokud w1 -> w2 a p je ve w2 false, má zvolený krok
zvýraznit w1, hranu w1 -> w2 a w2 jako counterexample successor.

V1 je dostupná on demand v Model Sandboxu. Používá stabilní occurrence paths,
truth-set overlay a modal witness/counterexample relations. Další zpřístupnění
v guided obsahu zůstává optional refinement.

5. NOVÉ GAMEPLAY / PUZZLE SMĚRY
===============================

5.1 Axiom Breaker
-----------------

[IMPLEMENTOVÁNO]

Vysoká hodnota, protože většina potřebného engine už existuje.

Koncept:
postavit model/frame/valuation, který falsifikuje cílový modal principle a přitom
zachová zadané relation properties.

Příklady:
- falsifikovat axiom 4 při zachování reflexivity
- najít counterexample k implikaci na serial frame
- zachovat symmetry a porušit transitivity
- odlišit formuli validní v jedné třídě rámců a nevalidní v jiné

Použít současné:
- semantic objectives
- frame-property constraints
- correspondence checks
- countervaluation/witness feedback

První Practice family obsahuje Break axiom 4 na reflexive frame a Break axiom 5
na serial frame. Obě mise mají validovanou reference solution.


5.2 Model Budget Challenge
--------------------------

[IMPLEMENTOVÁNO]

Úlohy typu:
- splň phi s nejvýše 3 světy
- použij nejvýše 2 explicitní hrany
- splň objective při zachování frame property
- vyřeš úlohu v omezeném semantic-change budgetu

Practice family obsahuje Split possibility a Two steps away s viditelnými
world/relation bounds a validovanými reference solutions.

Terminologické pravidlo:
řešení není "minimal" jen proto, že se vešlo do malého boundu.

Používat:
- Model Budget Challenge
- Small Model Challenge
- within N worlds/edges

Výrazy:
- minimal model
- shortest solution

používat pouze tehdy, když aplikace optimalitu skutečně dokazuje.


5.3 Distinguishing Formula / Formula Guessing
---------------------------------------------

[LATER / P2]

Koncept:
na konečném modelu a zvoleném target world w0 zadat formuli, jejíž truth set
odpovídá požadované množině, často pouze {w0}.

Matematická hodnota:
- test modal expressivity
- přímá vazba syntaxe na truth sets
- přirozené napojení na bisimulaci

Důležité:
ne každý svět lze modální formulí odlišit. Bisimilární světy jsou základní
counterexample k naivnímu předpokladu, že taková formule vždy existuje.

První verze:
- ověřit submitted formula na zobrazeném konečném modelu
- vyžadovat správný truth-set condition
- délku formule / modal depth zobrazovat deskriptivně nebo jako optional bonus

Nevyžadovat "nejkratší formuli", dokud optimálnost neumíme dokázat.

Ideální timing:
po Bisimulation Lab.


6. NOVÉ MATEMATICKÉ TOOLS A MAJOR MODULES
=========================================

6.1 Standard translation do first-order logic
---------------------------------------------

[NEXT NEBO EARLY P2]

Relativně malý a matematicky hodnotný tool.
Nevyžaduje obecný first-order theorem prover.

Implementovat syntax transformer / pretty-printer:

ST_x(p) = P_p(x)
ST_x(¬phi) = ¬ST_x(phi)
ST_x(phi ∧ psi) = ST_x(phi) ∧ ST_x(psi)
ST_x(phi ∨ psi) = ST_x(phi) ∨ ST_x(psi)
ST_x(phi → psi) = ST_x(phi) → ST_x(psi)
ST_x(□phi) = ∀y (Rxy → ST_y(phi))
ST_x(◇phi) = ∃y (Rxy ∧ ST_y(phi))

Možné UI:
- Standard Translation panel v Reference nebo Lab
- copy Unicode
- copy LaTeX

Priorita:
nízké architektonické riziko, vysoká výuková hodnota a přirozený most mezi
modální sémantikou a first-order model theory.

Toto není souhlas s implementací full first-order logic modulu nyní.


6.2 Bisimulation Lab
--------------------

[MAJOR NEXT, P1]

Nadále preferovaný první nový velký Lab module po PC QA a menších P1
refinements.

Doporučené fáze:

V1: BISIMULATION CHECKER
- porovnat dva pointed finite models nebo dva světy
- spočítat/ověřit maximální bisimulation relation
- ukázat atom mismatch
- ukázat forth violation
- ukázat back violation
- vizuálně párovat related worlds
- vysvětlit, proč dva pointed models jsou nebo nejsou bisimilar

V2: BISIMULATION CONTRACTION
- spočítat bisimilarity classes uvnitř jednoho finite modelu
- vytvořit quotient/contracted model tam, kde je to korektní
- ukázat mapování original worlds -> quotient classes
- vysvětlit zachování modálních formulí

V3: BISIMULATION GAME
- Spoiler vs Duplicator
- finite-round nebo open-ended režim
- zvýraznění legal replies
- napojení na modal indistinguishability a modal depth

Pro finite models preferovat relation refinement / greatest fixed-point
algoritmus před brute force.


6.3 Generated submodels a modal depth
-------------------------------------

[LATER / P2]

Cíle:
- generated submodel z vybraného světa
- zobrazení unreachable a lokálně irrelevantní struktury
- depth-n neighborhood
- napojení modal depth formule na část finitely branching modelu relevantní pro

Nezobecňovat příliš:
modal depth neznamená, že každý problém s nekonečným nebo infinitely branching
modelem je tím automaticky konečný.


6.4 Filtration Lab
------------------

[LATER / P2]

Didaktický workflow:
1. vybrat model
2. zvolit nebo odvodit konečnou množinu Gamma vhodně uzavřenou pod subformulemi
3. spočítat world equivalence podle shody na Gamma
4. vizualizovat equivalence classes
5. vytvořit filtered quotient
6. porovnat truth formulí z Gamma před a po filtraci
7. vysvětlit truth-preservation theorem

Staging:
- V1 může fungovat nad explicitním finite modelem
- V2 lze později propojit se symbolic/generated infinite models

Netvrdit, že UI "zredukuje libovolný nekonečný model", pokud umí pracovat pouze
s explicitním finite inputem.


6.5 Tableaux a countermodel generation
--------------------------------------

[LATER / P2-P3]

Schválený směr, ale jde o větší subsystém než evaluator feature.

Doporučené fáze:

V1:
- analytic semantic tableaux pro K
- explicitní branch expansion
- open/closed branch visualization
- countermodel extraction z open branch

V2:
- kontrolované rozšíření pro T, D, K4, S4 a S5
- explicitní vizualizace frame-condition propagation

V3:
- optional automatic search
- vložení generated countermodelu do běžného model workspace

Kritické pravidlo:
tableau-generated countermodel není automaticky minimal countermodel.

Tlačítko "Find minimal countermodel" použít pouze tehdy, pokud máme algoritmus,
který dokáže minimalitu v přesně popsaném finite search space, například
exhaustive search podle rostoucího world count a jasně definované sekundární
metriky.

Jinak používat:
- Find countermodel
- Generate countermodel
- Search up to N worlds

7. SPECIALIZOVANÉ MODÁLNÍ LOGIKY
================================

7.1 Multi-agentní epistemická logika
------------------------------------

[LATER / P3]

Pravděpodobný první velký specialized logic module po dozrání normal-modal
toolsetu.

Potřebná architektura:
- agent-indexed relations R_a, R_b, ...
- indexed modalities K_a phi
- vizuálně odlišitelné relation layers
- agent/group selection
- frame constraints per agent tam, kde dávají smysl

Group operators:
E_G phi = everyone in group G knows phi
C_G phi = common knowledge in group G

Common knowledge vyžaduje reachability přes reflexive-transitive closure unionu
relevantních agent relations, ne pouze další lokální unary operator.

- GPT nerozhoduje matematickou správnost
- používat jeden workspace/evaluator napříč Learn, Campaigns, Lab a Create
- authored content držet data-driven, kde je to praktické
- semantic state oddělit od presentation/layout state
- nedělat full rewrite App.tsx
- extrahovat focused modules postupně
- zachovat import/export/share a local data compatibility
- nové logic engines přidávat až pro konkrétní modul

Každá built-in authored mise má mít:
- valid initial model
- parseable formulas, pokud je vyžaduje objective
- reachable objective
- kompatibilní a viditelné constraints
- verified reference solution nebo jiný reprodukovatelný důkaz řešitelnosti
- matematicky správný feedback
- regression test nebo reprodukovatelnou kontrolu

Nikdy nezaměňovat:
- M,w |= phi
- M |= phi
- F |= phi
- validitu na jednom finite frame
- validitu v třídě frames
- theoremhood v modální logice

Minimalita:
- world count, edge count a edit metrics lze zobrazovat deskriptivně
- matematickou minimalitu nelze tvrdit bez důkazu
